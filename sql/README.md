# Database layer and PostgREST API

The Delphi data are read straight from the PostgreSQL database of the
LimeSurvey instance. Nothing in LimeSurvey is modified: these scripts add two
schemas next to its tables.

| Schema | Contents | Exposed by PostgREST |
|---|---|---|
| `delphi` | rounds, a JSONB snapshot of the responses, participant names, answer codes | never |
| `api` | pseudonymous round views, panel list, issues, feedback function | yes |

LimeSurvey stores responses with version-specific names (LimeSurvey 7:
`lime_responses_<sid>` with columns `Q40`, `Q43_S97`; LimeSurvey 6:
`lime_survey_<sid>` with columns `<sid>X6X40`, `<sid>X6X43STAT`). The function
`delphi.answer_keys()` maps both conventions to question codes, the same keys
as LimeSurvey's CSV export (`GRIDS[HEX]`, `GRD[P2_square]`), and
`delphi.sync()` stores every submitted response as JSONB under those keys. All
other objects work on that JSONB and do not depend on the LimeSurvey version.
Tested with LimeSurvey 6.17 and 7.6, PostgreSQL 16 and PostgREST 14.

## Install

In the LimeSurvey database, as its owner (the script creates the roles
`delphi_anon` and `delphi_coord` if they do not exist):

    psql -d limesurvey -f sql/10_core.sql -f sql/20_codes.sql -f sql/30_api.sql

The scripts are idempotent: run them again after updating the repository.
`20_codes.sql` is generated by `scripts/limesurvey_build.py` from
`scripts/survey_schema.py`; do not edit it by hand.

## Run a round

Register the round once its two surveys are imported into LimeSurvey:

    insert into delphi.round (round, seq, sid_geometry, sid_applications)
    values ('round-01', 1, 100101, 100102);

Copy the submitted responses into the snapshot (at closure; it can be run at
any time to refresh):

    select * from delphi.sync('round-01');

Close the round, which makes its pseudonymous data public through the API:

    update delphi.round set closed_at = now() where round = 'round-01';

At the end of the consultation, publish the panel list:

    update delphi.round set panel_published_at = now() where round = 'round-01';

Retention: once the results are published and the panel list is in the
repository, remove names and sensitive texts from the snapshot, then delete
the participant tables and responses in LimeSurvey:

    select delphi.purge('round-01');

## API

| Endpoint | Content | Anonymous access |
|---|---|---|
| `GET /rounds` | rounds and their status | always |
| `GET /respondents`, `/responses`, `/familiarity`, `/filter_votes`, `/grades`, `/open_answers`, `/panel_profile` | the pseudonymous round files | after `closed_at` |
| `GET /panel`, `/composition`, `/coi_anonymous` | panel list and counts | after `panel_published_at` |
| `GET /issues` | problems to fix before publishing | never (coordination only) |
| `POST /rpc/feedback` | a respondent's previous answers next to the panel's statistics | always, with the participant's own token |

Filter by round with `?round=eq.round-01`; ask for CSV with the header
`Accept: text/csv`. `scripts/postgrest_fetch.py` downloads a round into the
repository in the usual file layout.

## PostgREST

Create the login role PostgREST connects with (choose a strong password):

    create role delphi_authenticator login noinherit password '...';
    grant delphi_anon, delphi_coord to delphi_authenticator;

Configure PostgREST from `postgrest.conf.example`: `db-schemas = "api"`,
`db-anon-role = "delphi_anon"`, a `jwt-secret` of at least 32 characters, and
`server-cors-allowed-origins` set to the LimeSurvey address, so that only its
pages can call the API from a browser.

The coordination authenticates with a JWT whose `role` claim is
`delphi_coord`:

    export DELPHI_JWT=$(python scripts/postgrest_jwt.py --secret-file ~/delphi-jwt-secret --days 30)
    python scripts/postgrest_fetch.py --round round-01 --url https://delphi.example.org/api

Keep the secret and the tokens out of the repository.

## Feedback in a later round's survey

In round 02, each panellist must see their own previous answer next to the
panel's median and interquartile range. A question of the round 02 survey can
fetch them with the participant's token, which LimeSurvey substitutes for
`{TOKEN}` in question texts:

```html
<div id="delphi-feedback"></div>
<script>
fetch("https://delphi.example.org/api/rpc/feedback", {
  method: "POST",
  headers: {"Content-Type": "application/json"},
  body: JSON.stringify({p_token: "{TOKEN}"})
}).then(r => r.json()).then(f => {
  if (!f || !f.relevance) return;
  // f.relevance: [{application_id, property, own, n, median, iqr}, ...]
  // f.grades:    [{property, geometry, own, n, median, iqr}, ...]
  // f.filter:    [{application_id, own, yes, no, unknown}, ...]
});
</script>
```

The function finds the token among the participant tables of the registered
rounds, takes the most recent closed round before the current one, and
returns only that respondent's answers plus aggregate statistics; an unknown
token returns `null`. To insert scripts in question texts, the LimeSurvey user
editing the survey needs permission to bypass the XSS filter (global setting
or superadministrator).
